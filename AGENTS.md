# Project rules
- Render all six legal routes through LegalLayout using raw markdown and GFM; empty files retain existing legal content until replacement copy arrives.
- Preserve `/why-moxie` as a replace-navigation redirect to `/why-moxiemo` so legacy links reach the canonical page without retaining an obsolete page in browser history.
- Mount one HelmetProvider at the app entry and use Helmet for new route-specific metadata, so route titles and self-referencing canonical URLs have a single lifecycle owner.
- Use RouteMetadata for Compare, the method article and Resources to scope Helmet tags and restore static fallback tags on unmount, so routes without head overrides keep their existing metadata.
- New blog posts use BlogArticle with optional hero content, byline and closing CTA overrides plus RouteMetadata, so existing posts retain their template and metadata lifecycles stay scoped.
- Render the MOXIE founder story image through MoxieBlogImage, so its featured, card and hero treatments share the uploaded image and centered cover crop.
- Mount one cookie consent controller at the app root; all optional script loaders must use window.moxiemoConsent before loading so choices apply across every route.
- Keep consent validation and persistence separate from the dialog; use Radix for modal focus management and an insert-only consent log for visitor evidence.
- Reload after analytics withdrawal to stop already-loaded Clarity code, because removing its script element alone cannot unload running third-party code.
- Keep public pricing data and offer rules in the pricing data module, shared by the pricing cards and comparison table and covered by concrete rate tests, to prevent inconsistent plan displays.
- Pass publicAssessment only from the public report route into the shared report renderer so public naming changes do not alter signed-in app screens.
- Keep CTA assignment, labels and consent-gated experiment tracking in ctaVariant; validate nullable submitted versions server-side so legacy sign-up paths remain compatible.
- Persist home first-100 brand counts through the existing waitlist handler with server validation; keep the column nullable for legacy and other forms so existing signup paths continue working.
- Keep the admin sign-up button test's counts, shares and export column list in src/lib/ctaResults.ts, and read tagged rows only through the admin function so names and emails can never reach the export.
- Keep /start parts isolated under pages/start with scoped styling and metadata; redirect /founding with replace navigation and preserve its query so campaign pages do not alter the main site.
- Use the shared joinFoundingList helper and visit-memory campaign module for /start forms; persist nullable UTM fields through join-waitlist so all campaign placements share attribution and response handling.
- Keep hero copy, typing transitions and consent-gated events in the start modules, with separate form/question panels and an openSeat event; auto-start assessment query visits through the existing step-one handler so normal assessments remain unchanged.
- Keep the how walkthrough and SVG ring isolated from the hero, with shared stage data and progress rules; route its final claim through openSeat so the existing founding form remains the only hero signup owner.
- Share the founding form between hero and section via its entry prop and unique field IDs; keep lower-section reveals in a reusable IntersectionObserver wrapper so signup attribution and reduced-motion handling remain consistent.
